Cet endpoint dépose un seul document par requête : un objet JSON (contenu en base64) ou un multipart/form-data. Le schéma du corps ne décrit que l'objet JSON.

En multipart/form-data, la requête porte deux parties obligatoires : `meta`, un objet JSON avec `type`, `title` et, facultatif, `comment` ; `file`, le fichier. Si la requête porte plusieurs parties `file`, seule la dernière est prise en compte.

Le fichier fait 20 Mo au plus : au-delà, le dépôt répond 400, code 1002, dans les deux formats. Formats acceptés : PDF, JPEG, PNG, WebP, HEIC et HEIF. Le format est détecté à partir du contenu du fichier.

Un document du même type au statut waiting_for ou to_verify est remplacé par le fichier déposé, qui passe à to_verify. Un document du même type déjà accepted ne peut plus être remplacé : le dépôt répond 409, code 3005, seulement si aucun document du type n'est waiting_for ni to_verify.

Un document du même type à signer (statut to_sign, par exemple une « Attestation de réparation ») ne se remplace pas non plus (409, code 3008) : l'assuré le signe depuis son espace client Colibri, aucune route de l'API ne permet de le signer.

Un sinistre clos, refusé ou abandonné n'accepte plus aucun document (409, code 3003), avant toute règle de doublon. Fonctionne aussi pour un sinistre hors pré-déclaration : le paramètre autoSubmit est alors sans effet.
